1. Прочитай `CLAUDE.md`, затем `docs/TEAM.md` (раздел «Participant 3 — Frontend»), `docs/API.md`,
   `contract/schemas.py`. Правила из CLAUDE.md обязательны. Работаешь **только в `admin-ui/`**.
2. Создай ветку `feat/ui-skeleton`. Сделай Next.js (App Router) + TypeScript + Tailwind в `admin-ui/`.
   - TS-типы руками по `contract/schemas.py` в `admin-ui/lib/types.ts`;
   - API-клиент `admin-ui/lib/api.ts`, базовый URL из `NEXT_PUBLIC_API_URL` (по умолчанию `http://localhost:8000`);
   - пока бэкенда нет — мок-сервер или mock-режим (`NEXT_PUBLIC_USE_MOCKS=1`) с данными только в `admin-ui/mocks/`,
     **выдуманными** по примерам из API.md (реальные тексты тикетов из данных кейса не использовать).
   Открой PR, когда страницы открываются и работают на моках.
3. Экраны (ветка `feat/ui-admin`):
   - **Очередь** (`/`): таблица тикетов из `GET /queue`, сортировка по приоритету и времени, фильтры
     priority / category / status, p0 визуально выделен, бейдж `needs_human`.
   - **Тикет** (`/tickets/[id]`): сообщения игрока и обвиняемого, извлечённые факты, категория/приоритет/confidence,
     причины `needs_human`, черновик ответа, где цитаты правил (`cited`) подсвечены.
   - **Действия**: «Отправить», «Править» (inline-редактор, сохраняется как `edit` с `final_text`), «Эскалировать» —
     все через `POST /tickets/{id}/action`, с обработкой ошибок и состоянием загрузки.
   - **Статистика** (`/stats`): данные `GET /stats`.
   - Форма «Новое обращение» → `POST /tickets` — для живого демо перед жюри.
4. Качество: ни одной неработающей кнопки, понятные пустые состояния и ошибки, аккуратный строгий интерфейс
   (это инструмент модератора, не лендинг), язык интерфейса — русский.
5. Когда Backend смержит API — переключись с моков на реальный сервис и проверь все сценарии вручную.

Не трогай ничего вне `admin-ui/`. Нужно поле, которого нет в контракте, — скажи мне, я передам Tech Lead.
