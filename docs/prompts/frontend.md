1. Прими приглашение в репозиторий (придёт на почту / в уведомления GitHub).
2. Проверь Node.js (нужна версия 20+): `node --version`. Если меньше или нет — `brew install node`.
3. Склонируй репозиторий:
```bash
cd ~ && git clone https://github.com/torgyndoshybekova-ops/support-copilot.git && cd support-copilot
```
4. Данные кейса фронтенду **не нужны**. Все примеры в интерфейсе — выдуманные, в `admin-ui/mocks/`.
5. Запусти Claude Code в корне репозитория: `claude` — и вставь промпт ниже целиком.

Ты — мой напарник-разработчик на хакатоне Decentrathon 6.0. Я — **Frontend Developer** в команде из 4 человек.
Мы в корне репозитория https://github.com/torgyndoshybekova-ops/support-copilot.

Правила из CLAUDE.md обязательны. Я работаю **только в папке `admin-ui/`**.

Что строим: интерфейс модератора игры Grand Mobile. Сервис сортирует обращения игроков (жалобы и репорты),
определяет категорию и приоритет p0–p3, пишет черновик ответа со ссылками на пункты правил и помечает, когда нужен человек.
Админ видит очередь, проверяет черновик и жмёт «Отправить», «Править» или «Эскалировать». Его правки сохраняются как обучающий сигнал.
Это главный экран на демо перед жюри — должен выглядеть как серьёзный рабочий инструмент, а не лендинг.

**Задача 1 (ветка `feat/ui-skeleton`)**:
- Next.js (App Router) + TypeScript + Tailwind в `admin-ui/`;
- `admin-ui/lib/types.ts` — TS-типы руками по `contract/schemas.py` (TriageRequest, TriageResponse, Ticket, ActionRequest);
- `admin-ui/lib/api.ts` — клиент, базовый URL из `NEXT_PUBLIC_API_URL` (по умолчанию `http://localhost:8000`);
- mock-режим `NEXT_PUBLIC_USE_MOCKS=1`, данные только в `admin-ui/mocks/`, **выдуманные** по примерам из API.md
  (10–15 тикетов разных категорий/приоритетов/языков: русский, узбекский латиницей, казахский; часть с `needs_human`).
Открой PR, когда страницы открываются на моках.

**Задача 2 (ветка `feat/ui-admin`)** — экраны (интерфейс на русском):
- **Очередь** `/`: таблица из `GET /queue`, сортировка priority → время, фильтры priority / category / status,
  p0 визуально выделен, бейджи `needs_human` и «дубль/спам», язык обращения.
- **Тикет** `/tickets/[id]`: переписка (игрок / обвиняемый), извлечённые факты (ник, пункты, есть ли видео),
  категория / приоритет / confidence, причины `needs_human` списком, черновик ответа. Цитаты правил из `draft_reply.cited`
  подсвечены в тексте и показаны чипами.
- **Действия**: «Отправить», «Править» (inline-редактор → `action: "edit"` + `final_text`), «Эскалировать» —
  через `POST /tickets/{id}/action`; состояние загрузки, обработка ошибок, после действия — переход к следующему тикету.
- **Статистика** `/stats` из `GET /stats`: распределение по категориям/приоритетам, доля «нужен человек», средняя задержка.
- **Новое обращение**: форма → `POST /tickets` (kind + текст + число вложений) — для живого демо перед жюри.

Качество: ни одной мёртвой кнопки, понятные пустые состояния и ошибки, горячие клавиши (например, `S` отправить,
`E` править, `X` эскалировать, `J/K` по очереди) — это сильно смотрится на демо.
Когда Backend смержит API, переключись с моков на реальный сервис (`uvicorn service.app.main:app --port 8000`)
и вручную пройди все сценарии.
